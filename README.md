Запускал локально на Windows, Python 3.12.4, VS Code с расширениями Python и Jupyter, виртуальная среда `.venv`. Перед Run All в первой ячейке достаточно указать `VARIANT = 4`: ячейка сама скачивает `get\_data.py` и данные варианта в папку `data/` (она в `.gitignore`).

pip install -r requirements.txt

## 5\. Выводы

* Классы сбалансированы: в породах 201–202 файла (всего 806, кошек и собак по 403), поэтому взвешивание классов не нужно, а при делении на train и val достаточно стратификации по породе.
* Размеры сильно разные: ширина 176–1024, высота 150–900 пикселей (медиана 500×375). Перед батчами нужен ресайз, при `cv2.resize(rgb, (224, 224))` исходный кадр 333×500 растягивается в квадрат и пропорции искажаются.
* Проблемных файлов в моём варианте нет: не RGB 0 из 806, формат не совпадает с расширением у 0 из 806. Проверка через Pillow всё равно нужна, потому что `cv2.imread` по умолчанию всегда отдаёт 3 канала и такие файлы (GIF под видом `.jpg`, оттенки серого, RGBA) не показал бы.
* Разметка неполная: XML-бокс есть у 403 из 806 изображений (50%), по породам 100 из 201, 100 из 202, 101 из 201 и 102 из 202. Для детекции размеченных кадров вдвое меньше, чем всего изображений.
* OpenCV читает цвета в порядке BGR: у `Ragdoll\_37.jpg` центральный пиксель `\[139 212 242]` в BGR и `\[242 212 139]` после `cv2.cvtColor`, а без перевода кошка на графике синяя.
* Типы `uint8` переполняются: `np.array(\[50, 200, 250]) + 100` даёт `\[150, 44, 94]`, а `cv2.add` упирается в 255 и даёт `\[150, 255, 255]`, поэтому арифметику над картинками нужно делать в `float` или через `cv2.add`.
